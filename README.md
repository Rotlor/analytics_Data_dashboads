# Аналитика вакансий Data & Analytics

ETL-пайплайн и хранилище данных для анализа вакансий hh.ru в сфере данных.
Проект охватывает 4 направления и 9 специализаций. SQL-запросы предназначены
для двух дашбордов в Redash: структура спроса и зарплатные ориентиры.

**Стек:** Python 3.12, Pandas, NumPy, PostgreSQL 15, Redash, Redis, Docker Compose.

## Что реализовано

- Сбор вакансий с веб-страниц поиска hh.ru: извлечение встроенного JSON из SSR-разметки.
- Загрузка справочников и курсов валют из API HH (`/dictionaries`).
- Хранилище `STG → DDS → DMA`, пакетная загрузка и обновление записей.
- Классификация ролей и предполагаемых грейдов, извлечение упоминаний технологий.
- Пересчёт валют и оценка Net с учётом базовой прогрессивной шкалы НДФЛ.
- Зарплатные квантили и SQL для дашбордов с фильтрами направления и грейда.
- Проверки качества данных и тесты расчётов, загрузки и SQL-витрин.

Отдельный модуль `src/enrich.py` предназначен для обогащения карточек через
`api.hh.ru/vacancies/{id}`. Он запускается вручную; обработка ответов и очередь
проверены тестами, но реальная загрузка карточек этим модулем не проверялась.
Показанный в дашбордах срез собран веб-парсером; описания в исходной версии
также извлекались из веб-страниц вакансий, с неполным покрытием.

## Запуск

Нужны Docker Desktop с Linux containers и Python для генерации локальных настроек.

```powershell
python -m src.init_env
docker compose up -d postgres redis
docker compose run --rm init-server create_db
docker compose up -d server scheduler worker
docker compose build etl
docker compose run --rm etl python -m src.pipeline --init-only
```

Redash доступен на `http://localhost:5050`. Источник данных внутри Docker:
host `postgres`, port `5432`, database `hh_dwh`; пользователь и пароль — из `.env`.
Команда `init-server create_db` нужна только при первом запуске нового стенда.

Данные и секреты в репозиторий не включены. Для сбора заполните в `.env`
`HH_USER_AGENT` именем приложения и контактной почтой: он используется при
запросе справочника API. `HH_ACCESS_TOKEN` передаётся в этот запрос, если задан.
Сами вакансии собираются веб-поиском:

```powershell
docker compose run --rm etl python -m src.pipeline --extract
```

Необязательное API-обогащение требует также `HH_ACCESS_TOKEN` зарегистрированного
приложения HH. После него нужно пересчитать витрины:

```powershell
docker compose run --rm etl python -m src.enrich --limit 50 --pause 1.2
docker compose run --rm etl
```

Поиск использует SSR-разметку hh.ru и зависит от доступности сайта.
Обогащение сохраняет статусы запросов и отложенные повторы; доступ API зависит
от авторизации и ограничений HH. Если STG уже заполнен восстановлением своей
БД, для пересчёта достаточно `docker compose run --rm etl` без нового сбора.

## Дашборды

Готовые запросы находятся в `sql/redash/`. В Redash параметры `role_family`
и `grade` настраиваются как Dropdown List и связываются с общими параметрами
дашборда. Значение `Все` снимает соответствующее ограничение.

## Ограничения

Выборка не представляет весь рынок РФ; активность вакансий не подтверждается.
Грейд может определяться по опыту, дедупликация предложений основана на эвристике.
Зарплатные показатели — расчётные оценки по опубликованным вилкам; при `n < 5`
презентационные запросы скрывают квантили. Исторические снимки пока не реализованы.

## Тесты

```powershell
docker compose run --rm etl python -m unittest discover -s tests -v
```

Для интеграционных тестов используйте отдельный тестовый PostgreSQL и переменную
`HH_TEST_POSTGRES=1`: тесты создают базы `hh_test_<uuid>` с правом `CREATE DATABASE`.
